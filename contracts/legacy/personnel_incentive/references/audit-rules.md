# 人员激励确定性规则

商品知识库统一指 MySQL `product_catalog.products`，按[数据库知识规则](../../../shared/product-database/audit-knowledge.md)
读取本次只读快照。人员核销不查询商品参考图片；当前匹配仅用数据库名称、编码与69码。

## 映射

- 结算映射前，每个汇总后的 Excel SKU 必须通过正式商品知识库：来源 69 码是有效 EAN-13 且
  严格匹配；随后来源商品名称只需在同码候选集中形成一个唯一的模糊相容匹配。不要求名称严格
  相等。
- 人员 Excel 不提供产品编码。为追溯返回选中知识商品的产品编码，但不要编造或要求 Excel
  编码字段。
- 准确 69 码没有目录商品、名称冲突，或多个同码商品无法通过名称唯一分辨时，保留诊断候选集
  但使知识门禁失败。在 Excel 或知识库更正前，受影响 SKU 的支持奖励为零。
- 高置信度要求条码在结算单上清晰印刷可见，并存在于程序读取的 Excel 中。
- 没有可见条码时，在剩余一行一条码约束下，优先接受只出现在一个尚未使用且通过知识门禁的
  Excel SKU 中的准确数量。缩短、拼错或被 OCR 误读的结算商品名称只是模糊辅助文字，不能排除
  该唯一路由。数量不唯一时，将结算文字与有知识支持的 Excel/目录名称及别名进行模糊比较，并
  要求一个可靠候选。两种结果都标记为中置信度；准确 69 码、数量和奖励均一致时直接通过，无需
  补交。
- 绝不能从 AI JSON 获取 Excel 商品名称或条码。
- 绝不能把两条结算明细映射到同一条码。候选有歧义或不存在时保持未匹配。

## 数量与奖励

- Excel SKU 数量是该条码所有有效明细行之和。
- 数量差为 `Excel 数量 - 结算数量`。
- 明细金额差为 `结算奖励 - 结算数量 × 单位奖励`，精确到人民币 0.01 元。
- 只有映射有效且 Excel SKU 也通过商品知识门禁时，数量支持奖励才是
  `min(非负 Excel 数量, 非负结算数量) × 单位奖励`。
- 存在转账证据时，建议核准金额不能超过实际申报、数量支持奖励或去重转账合计。

## 转账与身份

- 一条 JSON 转账记录代表一个业务事件；`occurrence_count` 记录多个可见视图，不乘算金额。
- 只有可见业务证据支持时才配对付款方/收款方视图，并保留配对局限。
- 优先按可见身份匹配门店。仅金额匹配只能验证金额多重集合。
- `identity_visible` 加收款人名称不足以验证门店；还需要 `store_name` 或已提供的对应关系。
- 日期验证要求完整 ISO 日期。只有星期/时钟信息的截图保持未验证。

## 结论

- 知识门禁失败、SKU 未映射、重复映射、数量不一致、期间不一致、明细计算错误或付款不足均为高
  严重度。
- 已接受的中置信度商品映射本身不是例外。收款人/门店关系不可见、日期不完整、少申报或声明
  合计差异，即使汇总金额一致也仍未解决。
- 只有所有必核控制都解决时使用 `pass`；金额得到完整支持但存在身份/说明局限时使用
  `conditional_pass`；只有部分得到支持时使用 `partial_pass`；其他情况使用 `human_review`。

## 面向人工的行名称

- 结算明细唯一解析到知识库商品时，只使用该商品的完整权威名称作为面向人工的标题；不要添加
  `结算第N行` 前缀。
- 将结算单图片中原始识别的商品文字保留在视觉证据列，使读者仍能看到提交材料实际内容。
- 未能唯一解析知识商品时，不要借用 Excel 或候选名称作为权威；标题保留识别出的结算文字，
  并单独展示失败匹配。

## 严格错误归因

客户文案执行[统一错误原因与处理方式规范](../../orchestrate-offline-audit/references/error-reasons.md)。以下归因事实写错误原因，建议只写独立处理方式，业务文件区域仅列实际相关 basename。

- 每个失败或未解决的面向人工行都必须列出准确的问题文件 basename。结论依赖另一来源时，
  还要列出准确的对照/基准文件 basename。
- 说明每个具名来源中已观察到的值或缺失的必填字段，再解释这些事实为何导致关系无法确认。
  笼统的关系标签不是错误原因。
- 对于收款人/门店/日期失败，指出相关转账截图缺少的完整收款人、门店对应关系或完整交易日期；
  需要对照时保留相关销售 Excel 文件名及必要业务事实，不追加已提交材料清单或核销影响。
- 对于申请/转账金额差异，明确结算单文件和转账截图，说明双方金额及准确差额；现有材料无法
  确定哪一金额具有权威性时也要明确说明。
- 补交动作只在处理方式列出受影响文件和必须提供的准确字段或更正关系。绝不能使用 `A ↔ B 无法确认`、
  `Excel门店与收款人无法逐一确认` 或其他没有来源的简写。
