# 统一资料输入目录

本地导入和 OSS 下载的原始 ZIP 统一保存在 `input/`，自动支持以下两种布局，也可以混合放置：

```text
input/
├─ SQ202511250016-HX202512300004-其他.zip
├─ 1bfee687aeb7a59f1571747a/
│  └─ HX202606040013-核销资料-诚成26年4月【堆头20家】.zip
└─ <其他任务ID>/
   └─ <原始文件名>.zip
```

默认读取本目录直接放置的 ZIP 和一级任务子目录中的 ZIP；每个目录最多 10 个 ZIP，至少要发现一个 ZIP。合并读取时，全部包共同受原有总解压文件数、总大小和嵌套深度限制。相同文件名或相同内容的包仍按各自来源独立处理，不展平、不覆盖、不自动去重。普通说明文件不作为输入，拒绝符号链接及目录联接。

从项目根执行：

```powershell
py -3 -B skills/orchestrate-offline-audit/scripts/run.py --run-id <YYYYMMDD-run-id> --producer-model codex --input-dir "input/<本次资料>.zip" --biz-type "<用户已确认的核销方式>"
```

使用 `--input-dir "input/1bfee687aeb7a59f1571747a"` 可只读取一个任务目录；使用 `--input-dir "input/SQ202511250016-HX202512300004-其他.zip"` 可只读取一个 ZIP。默认扫描会读取两种布局中的全部 ZIP，包括已留存的任务原包；单独复跑请指定具体文件或任务目录。

OSS 接口按 `verifyCode`、`analyzeId`、`downloadUrl`、`bizType` 接收任务，下载并验证后保存到 `input/<job_id>/<原始文件名>.zip`，正式 runner 只读取该任务目录。每次终态重交使用新任务目录，避免同名覆盖。已验证原包在任务成功或失败后保留；不完整、超限或无效下载会清理。任务回执仍保存在 `worktrees/.intake/jobs/`。签名 URL 不落盘。

本地ZIP须先询问用户本次核销方式，收到答复后再运行；本次请求已明确方式时直接沿用。可选：条码费、陈列堆头、人员激励、POS达标激励、搭赠、KT板等物料制作、补差、外采赠品。多个包须逐包明确方式，同类型可合并，不同类型分别通过`--input-dir`和`--biz-type`运行，不能替用户猜选类型。

交互终端未传`--biz-type`时会列出八种方式并等待选择，没有默认值；非交互调用缺少或传入空白方式时停止，提示先询问用户，不读取ZIP、不调用AI、不创建核销记录。`--scenario`不能代替确认。OSS继续按`bizType`精确匹配对应Skill；两种入口都不能按资料或文件名改变已确认的类型。资料问题正常完成并列出具体问题，满足资料要求后只按本类审核要点检查。完整规则见[项目说明](../README.md)。本地复跑不因文件位于任务目录而自动发送业务回调。

每次核销独立发布 `worktrees/<压缩包名>-<上海时间>/`，包含自包含 HTML、摘要、manifest/snapshot 和证据，不覆盖历史。解压内容、模型工作区和其他中间文件结束后自动清理。原始 ZIP 和任务子目录不进入 Git，本说明文件是本目录唯一受跟踪文件。
