# ZIP 输入入口

本目录直接放置一至十个原始 ZIP，不要手工解压或放入其他文件：

- 人员激励包：1 份销售 Excel、1 张名称可识别的结算单图片、至少 1 张转账或红包截图，不含 PDF；
- 堆头陈列包：1 份销售 Excel、1 份合同 PDF、至少 1 张现场照片。
- 海报/物料制作包：1 张签章促销合同、1 张发票或收据、1 张客户盖章结算单、1 个现场返图 ZIP；POS 等无关材料会被排除。
- 其他费用包：文件名明确标记“其他”，无 Excel 和嵌套 ZIP，包含 1 份签章促销合同、1 份客户盖章结算单、至少 1 份独立协议/合同/发票/收据，以及按类型提供的活动照片、POS 或特殊审批证明。能归入现有类型的费用不得走“其他”。
- 维护费用包：文件名明确标记“维护费用”或“维护费”，提供经销商盖章POS、唯一POS电子表、具体费用协议/相关文件/活动期照片、公司统一模板经销商盖章结算单和唯一签章促销合同；缺失角色进入错误清单，多份电子表/合同/结算候选因无法唯一绑定而停止。
- 额外搭赠包：文件名明确标记“额外搭赠”或“搭赠”，无 Excel 和嵌套 ZIP，提供签章促销合同、经销商盖章结算、系统销售/出货明细、活动期门店小票和活动照片。通用相机文件名允许按可见正文确定角色；缺失角色进入错误清单，重复合同/结算/出货候选停止。
- 价格补差包：文件名明确标记“补差”或“价格补差”，提供签章促销合同、统一模板经销商盖章结算单、经销商盖章POS、唯一POS电子表，以及一个仅含现场图片的照片RAR。所有活动门店都须有活动期内日期/地址/拍摄时间水印和活动价清楚的照片；缺少电子表或照片覆盖不足进入错误清单。
- POS达标激励包：文件名明确标记“POS激励达标”“POS达标激励”或“POS激励”，提供经销商盖章逐门店POS、唯一POS电子表、渠道资格和目标档位/比例/上限明确的签章合同、统一模板经销商盖章结算，以及满减活动水印照片、小票或其他存在证明；缺失角色进入错误清单。
- 进场费/条码费包：文件名明确标记“进场费”或“条码费”，提供唯一双方签章进场费合同/产品推广协议、一个仅含进场/上架照片的RAR，以及合同要求的系统扣款凭证；照片文件夹名只用于路由，须以照片自身水印核对合同门店。
- 客户自采赠品物料包：文件名明确标记“自采赠品物料”“自采赠品”或“自采物料”，提供唯一签章促销合同、唯一统一模板客户盖章结算单、唯一发票/收据、付款记录、经销商盖章POS视觉件、独立POS电子表，以及一份活动返图 `.xls`。该旧格式工作簿只用于逐门店提取返图，不能替代POS电子表；每张返图仍须用自身像素证明日期、地址、拍摄时间、促销内容和自采赠品。

可以单独提交任一类型，也可以多类各一份；同一类型最多一份。维护费用、额外搭赠、价格补差、POS达标激励、进场费和客户自采赠品物料均独立于其他费用；样例资料不全时会在结果中列出缺失项。只核销其中一类时追加 `--scenario personnel_incentive`、`--scenario promotional_display`、`--scenario poster_material`、`--scenario other_expense`、`--scenario maintenance_fee`、`--scenario giveaway_promotion`、`--scenario price_difference_support`、`--scenario pos_target_incentive`、`--scenario entry_fee` 或 `--scenario self_procured_gift_material`。

在项目根运行：

```powershell
py -3 skills/orchestrate-offline-audit/scripts/run.py --run-id <YYYYMMDD-run-id> --producer-model <producer-model> [--scenario <scenario>]
```

程序会安全检查、自动分类并在临时目录解压。类型未知、同类重复或材料角色无法唯一绑定时会停止并提示；维护费用中可明确识别的缺失角色会进入正式错误清单。
最终档案目录只使用业务日期与实际模型名，例如 `worktrees/20260818-codex/`；同日期、同模型重跑时追加 `-1.1`、`-1.2`，不生成每次运行独立的 HTML 或 Excel。

OSS 自动投递不会把远程对象复制到本目录。启用的工作台服务会把每个 OSS ZIP 持久下载到相邻的 [`input-oss/<job_id>/`](../input-oss/README.md)，校验后把该任务子目录交给同一个正式 `run.py`；因此本目录中的人工材料与 OSS 自动任务不会互相覆盖或混跑。接口配置和请求格式见根目录 [`README.md`](../README.md#oss-自动投递接口一期)。

如果这里放入的是一个尚未登记的新业务类型，并且同时提供了业务规则提示，请先使用
`skills/create-offline-audit-scenario/SKILL.md` 完成“新场景生成与接入”。开发阶段的未知 ZIP
不会被正式 `run.py` 猜测或自动套入某个现有场景；新场景完整验证并登记后才能正式运行。
