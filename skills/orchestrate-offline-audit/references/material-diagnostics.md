# 已知类型的材料问题继续分析

用户要求 ZIP 名称已唯一确定核销类型时，内部文件误命名、缺件或多交仍继续读取已提交材料，
在最终报告和 OSS 回调中明确列出缺失、重复、无法读取及需确认的材料。
2026-09-11 的补充要求明确：ZIP 名称无法唯一确定核销类型时直接打回，不调用 AI，不进入本材料诊断流程；必要归档安全校验保持执行。

客户文案必须执行[统一错误原因与处理方式规范](error-reasons.md)：错误原因只写具体错误事实，建议只写独立处理方式；涉及的业务文件区域只列相关实际文件 basename；回调摘要只含原因。下述逐文件角色、可见事实、置信度、页码及限制保留在内部技术证据，不能拼接成客户文件区域的说明。

仅对已知核销类型，AI 逐项盘点图片和 PDF 的可见内容，以稳定文件 ID 返回角色、置信度、标题、
印刷单号/页码、可见事实和读取限制。ZIP 名称中的唯一已登记类型标记决定使用哪一套核销规则；文件名不能证明文件中的业务事实。
不读取销售 Excel、历史结果、其他案件或缓存，不计算金额，不作核销决定。
模型权限、认证、超时、执行失败不能冒充已完成材料分析。

角色包括签署的促销合同、结算单、盖章 POS、活动照片、发票/收据、付款记录、
支持文档、系统销售/出库单、门店收货凭证、专项审批、系统扣费证明和进场合同。
可见信息不足时使用 unknown；普通场景照片不得凭文件名升级为活动执行证据。
已签角色的分类只表示文件用途，不能代替后续对双方签章、日期、金额和履约条件的审核。

已登记类型是人员激励、堆头陈列、海报/物料、其他费用、维护费用、额外搭赠、
价格补差、POS达标激励、进场费和自采赠品物料。
按 ZIP 名称中的唯一已登记标记分类。已写“维护费用”的包始终使用维护费用规则，不因图片提及人员激励、价格补差或陈列而改类、要求确认核销类型，或套用其他类缺件清单。
AI 只提取各文件实际用途与可见事实；候选类型即使保存在技术证据中，也无权改写 ZIP 分类。
ZIP 名称没有标记或含多个类型标记时，只生成确定性的分类拒绝报告，不解读该包内部材料、不调用 AI，也不从材料结构猜测类型或虚构缺件、重复、不可读等材料问题。分类拒绝按正式流程持久化并正常 OSS 回调，不冒充材料分析完成。混合多包中只有无法唯一分类的包被打回，其余已知类型继续正常审核或本材料诊断。公开契约为 `unclassified_archive_policy=reject_before_ai`。拒绝结果独立使用 `classification_rejection`，不复用 `material_diagnostic` 或视觉证据；分类拒绝仍须完整递归校验归档安全。

文件字节相同由程序确认重复；同角色多个不同文件只表示角色冲突或需确认，
不能直接声称业务重复。同一印刷单号的不同页可以属于同一文档；编号和页码必须可见，
不能凭相似模板、相同主体或金额强行合并。业务结算、供应商账单和付款/扣费凭证应分别识别用途。

确定性程序结合全量安全文件清单和通过 Schema 的视觉盘点生成材料问题。
无法读取或角色未明时应说“尚无法确认是否已提交”，避免把未识别误写成未提交。
用途未明或格式不支持文件的原因使用实际文件 basename，完整来源路径留在技术 JSON；缺失清单不能因为分批、分组或摘要长度丢失。
诊断完成不等于业务核销通过。存在材料阻断时，暂缓核销并回调明确问题；
安全路径、加密/损坏归档、超限和模型配置错误仍保留真实运行失败。
