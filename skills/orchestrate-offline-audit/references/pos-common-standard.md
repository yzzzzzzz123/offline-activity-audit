# POS通用核对

用户2026-09-22确认，八类核销只要实际涉及POS均使用本标准。先有Excel，再在相同内容上盖章，所有POS数据以Excel为准。盖章版保留现有资料门禁；字段、商品、计算、结算销量和赠品公式中的实际销量均只读取Excel。没有POS且原清单不要求POS的，不新增必交资料；实际提供时按现有两版成套口径盘点。

| 必含信息 | 核对方式 |
| --- | --- |
| 活动时间 | 从本次POS读取；其他资料不补写该字段。 |
| 商品SKU/编码（69码） | 读取完整69码并与商品库原值核对，不截断、改写或模糊匹配。 |
| 商品名称 | 查询商品库，允许简称或模糊匹配，结合69码须能唯一对应；明确规格、款式不能冲突。 |
| 销售数量 | 保留本次POS原值，参与金额及数量合计复算。 |
| 销售单价 | 保留本次POS零售单价，不能代替合同约定的奖励或补差单价。 |
| 销售金额 | 按原精度复算数量×销售单价；列示金额不小于复算金额。 |
| 销售金额及数量合计 | 金额合计不小于对应明细金额之和，数量合计等于对应明细数量之和。两项合计都须有。 |

只必含上述5+2项。缺项即不完整，具体指出Excel缺什么，不说整份文件未交。额外的产品编码及其他列不审核；即使标为我方编码、与库内不一致或归属不明，也不报问题，不用它筛选或排除商品。商品名称＋69码仍须查库且能唯一对应。此口径覆盖此前“填写了我方产品编码就必须一致”的要求。

先从本次全部POS Excel逐行提取商品名称和69码，再查询本次商品库快照。相同身份可复用核对结果，Excel的全部商品行及来源均保留。名称模糊核对只看轻量身份记录；不读取OSS清单、不下载商品图。照片外观审核另外遵循[按需取图](product-photo-reference.md)。

商品在库内找不到时，直接写“商品名称或69码：库内无参考商品”。名称不符、名称与69码不对应、存在多个候选、无法读清以及数据库故障分别处理，不能全写库内无商品。库内记录只作身份参照，不能补写原表缺项或销售事实。数据库连接失败属于系统故障，不能假装查库成功。

本标准不恢复POS印章、双版一致性或EAN校验位的独立审核。盖章版不覆盖Excel，也不据两版差异另报问题。Excel缺字段或看不清时，具体说明Excel的缺口，不用盖章版、合同、结算单或数据库补齐。

用户最终澄清：合同与结算申报单价必须相等，合同2元时申报1.9元也不符。数量仍按已有一致要求；只有最终结算金额允许抹零或四舍五入，且仅允许品牌方占优。按已有金额审核项核得100.005元时，结算100元可以，100.01元不可，不先将参照值舍入后比较。此金额例外不能放宽单价一致或另造结算公式；AI继续列出具体问题供人工复核，原文0核销后果保留为规则出处。确认记录见[业务问题记录](business-questions-20260921.md)。

假设例子：名称“参半蜜桃喷雾20ml”和69码唯一对应库内商品，商品身份核对通过；另填产品编码4362235，即使与我方产品编码不同，也不影响结论。Excel销量100支、盖章版110支、结算单100支时，已有结算销量检查按Excel的100支比较；不新增两版差异问题。
