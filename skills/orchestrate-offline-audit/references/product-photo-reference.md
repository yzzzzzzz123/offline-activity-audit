2. 优先用原文准确产品编码，或产品名称加69码定位。用户进一步确认：商品名称允许简称，核心是能唯一对应，不要求逐字相同，也不强制补齐另一字段。简称先与库内轻量身份信息核对含义，保留规格、款式及组合装等区别；只读有对应条码的候选，没有条码时核对已有名称的候选。所有可能候选核对后只有一个可确认的编码才取图；有多个可能或明确冲突时不猜选。候选很多时分批读取文字，不能看到第一批有一个就认定全库唯一。
3. 按产品编码去重，先筛选数据库行，再读取这些行的`image_manifest_key`和对应OSS细节图。数据库轻量身份索引不等于图片库；未选中商品的清单和图片均不请求。同商品跨门店、跨照片复用本次已校验图片，不按照片次数重复下载。
4. 宿主在私有认证下验证清单身份、对象路径、完整字节、大小、图像尺寸和SHA-256，再把对应图片交给隔离模型。仅下载到任务临时目录，退出后清理；模型不接触凭据或签名URL。每次核销重新读取数据库，不使用历史核销图片缓存。
5. 模型同时查看本次现场照片和所需商品参考图，辨认包装、规格、款式及其他清晰可见的区别。合同和图片库只提供应核对的商品及外观，现场是否出现必须由实际照片证明；模糊画面不能从参考图补写成可见。包装相近而无法区分时如实说明，不只凭品牌或主色判定对应SKU。

| 现有场景 | 使用边界 |
|---|---|
| 条码费 | 逐店核对协议约定全部SKU在现场清晰可见，同店多图可补齐；不能用另一门店照片补齐。 |
| 人员激励临促 | 已有每店每天照片中需要辨认对应产品时按需取图；不增加每个人或固定照片张数要求。 |
| 陈列堆头 | 已有实物/物料品牌判断需要识别具体商品时使用，不变成必须陈列合同全部SKU。 |
| 搭赠、线下补差 | 已有现场商品、活动或价格对应需要辨认SKU时使用；纯小票分支和纯文字判断不下载商品图。 |
| 外采赠品 | 只在已有照片商品对应确需我方商品外观时使用；外采赠品不强制登记我方商品库，不新增产品编码或69码资料要求。 |
| KT板等物料制作、POS达标激励 | 当前没有现场SKU识别审核项，不下载商品细节图；实际涉及POS时仍查商品库核对Excel中的名称和69码。POS额外产品编码及其他列不审核。 |
