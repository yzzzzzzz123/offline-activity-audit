# 1.4.1 分析维度

本项目以《小阔科技线下核销方案》1.4.1 为总控框架。主 Skill 必须在两个业务子 Skill 完成专业核验后，逐场景覆盖下列七项；每项都要输出“实际检查、证据结论、能力边界、补证要求”，不能用总金额一致代替。

| 大类 | 检测内容 | 方案中的判定标准 |
|---|---|---|
| 真实性验证 | 文件是否被篡改/伪造 | EXIF 信息完整性、图像指纹比对、水印一致性、数字签名验证 |
| 真实性验证 | 照片是否为现场实拍 | GPS 坐标与申报门店匹配、拍摄时间在活动周期内、设备信息一致 |
| 真实性验证 | 文件是否重复使用 | 感知哈希（pHash）去重、跨活动文件复用检测 |
| 合规性审查 | 文件格式是否符合要求 | 文件类型、分辨率、大小是否在允许范围内 |
| 合规性审查 | 费用金额是否合理 | 费用明细金额与活动预算比较，偏差超过 30% 标记异常 |
| 合规性审查 | 票据信息是否完整 | 发票代码、号码、金额、日期、购销方信息完整性 |
| 合规性审查 | 合同条款是否匹配 | 合同约定金额不低于发票总额，付款周期与开票日期一致 |

## 判定口径

对每个场景分别使用以下状态，不能把缺证写成通过：

- `通过`：标准要求的关键证据全部存在，且未发现冲突。
- `部分通过`：部分控制已通过，但仍有具体门店、文件或字段未通过。
- `部分验证`：执行了可用的技术检查，但原方案要求的能力没有全部具备。
- `证据不足`：该控制适用，但输入未提供作出判断所需的证据。
- `本案未触发`：输入不含该类材料，且当前业务规则未把它列为必交件；不得写成“通过”。

## 真实性边界

- SHA-256 只能固定收到文件后的字节身份，并发现完全重复；它不能证明文件在提交前从未被修改。
- dHash/pHash 只能筛查视觉相同或近似的复用候选；它不是像素级篡改鉴定，也不能单独证明现场真实性。
- 画面水印属于可见内容。没有可验证的 EXIF/GPS、设备信息或可信时间戳时，水印不能被描述为独立定位证明。
- EXIF 缺失表示该验证路径不可用，不等于照片必然伪造。
- 没有数字签名时必须写“未提供/无法验证”，不能用文件哈希代替数字签名。
- 只在本次提交包内去重时，必须明确写“跨活动复用未验证”；跨活动检查需要历史指纹库。

## 合规性边界

- “文件可以打开”只证明可读性。若未提供允许的文件类型、最低分辨率或大小阈值，只能判定为部分验证。
- 30% 规则必须使用独立的活动预算口径。没有预算表时，不得把申报金额自行当成预算；可以另行报告结算、合同、转账和申报之间的偏差。
- 没有发票时，先判断该场景是否要求发票。若规则未要求，标记“本案未触发”；若制度要求但未提交，则标记“证据不足/补证”。
- 合同检查要拆成金额上限、活动期间、门店/执行标准、付款周期和发票日期等子项。无发票或无付款周期时，只能对已有条款给出部分结论。

## 两个子场景的落点

### 人员激励

- 业务主控制是销售 Excel 与最终结算单逐 SKU、逐数量 1:1 勾稽，再核对奖励单价、行金额、门店应付和去重转账。
- 转账截图金额一致不等于收款身份、转账日期或真实性已验证。
- 本场景未提供现场陈列照片、合同、预算表或发票时，对应的 1.4.1 控制按“证据不足”或“本案未触发”展示，不影响 SKU 数量事实，但要保留能力边界。

### 堆头

- 业务主控制是合同 20 家门店逐店绑定照片，并分别检查照片存在、活动期、门店地点、陈列标准和重复情况。
- 经销商汇总销售只能作为活动总体销售支撑，不能替代合同门店逐店执行证据。
- 合同约定金额可以作为现有合同口径比较申报额，但若没有独立预算表，应明确这是合同口径而不是独立预算验证。
