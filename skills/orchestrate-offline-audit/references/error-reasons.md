## 错误原因

- 资料门禁未满足时，页面、摘要和回调列出具体缺少、多余或不能确认的资料及相关文件；正常完成检查，不报核销失败。新OSS请求已由bizType确定类型，只列本类型的缺项、多余资料及相关文件，不写其他类型的假定缺件。
- 进入业务审核后的每条错误写清哪份资料、哪家门店/哪天/哪件商品或必要的真实位置，实际看到了什么，以及哪项不符合已确认标准。只有缺材料时写缺哪份；缺字段时写缺哪项。不同商品、门店、日期的问题不能因同一类别而丢失。
- 金额、数量或单价有问题时，按需要写出双方原值、单位及差额，让客户能找到并理解差别；不用内部变量名或只写“数值不匹配”。只说明本类审核栏已经要求的比较或计算问题。
- bizType选定Skill后，只有本类资料门禁满足才进入业务审核。缺项、多项、条件不明正常完成门禁检查，逐项列具体问题，不改投其他类型。bizType为空或不能识别时输入失败，回调固定提示“无法识别核销类型”。
- 只有本类审核栏明确要求的盖章、水印或金额不合规，才形成业务检查失败。看不清时写清哪份文件的哪处模糊、哪一项读不出来，或缺少哪份用于比较的资料；不能只写“无法核验”，也不能改写成未交。没有充分事实不能写成造假、超期或金额填错。
- 读取权限、模型连接、依赖或渲染故障属于系统执行失败，不能写成客户缺件或照片不清。
- 原始单元格由程序读取；金额、数量逐字引用后复算。仅比较本次资料中口径对应的原值；销售单价不能当奖励单价，结算不能自证申请。
- 不写过程、通过事实、置信度、汇总数量、影响、建议或笼统结论；不重复错误标题。只合并完全相同的原因，不截断。

## 统一用业务人员能懂的说法

| 内部名称或不清楚的说法 | 客户小结和后台业务页面怎么写 |
|---|---|
| POS | 销售明细；需要区分时写销售明细Excel、销售明细盖章版 |
| SKU、69码 | 商品、商品条码；用真实商品名称或条码定位 |
| 水印要素缺失 | 仅在本类审核栏要求相应字段时，说明照片上具体缺哪项 |
| 无法核验、识别不足 | 印章模糊，看不清公司名称；或未提供申请金额，不能比较金额等具体原因 |
| 口径不一致 | 销售单价与奖励单价不是同一项；或两份表的数量单位不同，说明实际差别 |
| `missing_material`、`unknown`、`not_met`、规则编号 | 不原样输出；只写保存事实支持的具体资料问题 |
| 证据链、闭环、来源绑定、流程中断 | 不写进业务原因；改写为具体哪份资料缺少哪项、哪处看不清或与哪份资料不同 |

以上是表达方法，不授权把一种实际状态改成另一种。结构化状态、规则编号和详细计算可保留在明确的技术区域，不能出现在客户业务原因或回调正文中。

## 文件与处理方式

文件区域只列关联的原始业务文件basename；不同来源同名文件分别保留。业务原因在确有定位需要时可说明真实页码、工作表、行或照片位置；没有保存依据时不能编造位置。完整路径、全部原始事实和计算明细保留在技术JSON。嵌套归档内照片列照片名，工作簿派生图片对应其父工作簿。

处理方式栏如有内容，只写与该错误对应的操作；建议不得进入错误原因或回调。正式流程不自动执行罚款、扣款或人事通知。

## 假设示例

- `结算单.jpg：未加盖客户印章。`
- `销售明细.xlsx中商品甲售出10件，结算单.jpg填写12件，多了2件。`
- `门店照片.jpg：照片上没有拍摄日期。`
- `本次临促活动为9月1日至9月3日，缺少甲店9月2日的临促照片。`

示例只演示表达，文件名、日期、门店、商品和数字必须来自实际材料；不是新增资料清单或审核项。培训可免POS两版，选择提交时成套；搭赠照片或小票二选一；补差可用小象超市截图；条码费审核栏只核对水印门店地址；地址查重先确认门店归属，已确认同店的多张照片不报重复，仅不同申报门店使用同一地址时提示核对。范围仍仅限本次核销单，不从资料说明增加日期、店名检查。

摘要按实际核销类型分节，每项仅列具体原因，与OSS回调的 `result` 完全一致。历史结果只读兼容投影，不重写其证据或自动重发回调。
