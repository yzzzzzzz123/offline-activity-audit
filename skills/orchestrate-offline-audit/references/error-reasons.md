# 统一错误原因与处理方式规范

适用于全部已登记核销 Skill、新增核销 Skill、材料诊断、分类拒绝及其客户文案。客户界面分别回答两件事：**错误原因说明哪里错，处理方式说明怎么处理。** 涉及的业务文件区域只列文件名。OSS 回调和 `ai-analysis-summary.md` 沿用只输出错误原因的契约。

## 错误原因

- 直接写具体错误事实，保留定位问题所需的文件名、对象、页或行、缺失字段，以及存在差异时的实际值、应有值和差额。只使用已保存证据及确定性结果，不新增推断。
- 同一问题有多个原因时逐项并列；相同原因可以合并，但不能丢失不同文件、对象或差异。标题已经说明的错误不在正文原样重复。
- 不写通过事实、分析步骤、已盘点或已识别的流水账、审核结论、核销影响、置信度、补交建议或操作。不要追加“因此暂不能核销”“请人工确认”“资料需补正”等通用结尾，也不要重复“错误原因”“识别结果”等字段标签。
- 区分缺失、不可读和关系不明：未确认用途的材料可能包含所需文件，不能直接断言未提交；盖章不清不能写成未盖章；两份不同单据不能仅因文件名相似就说重复。只有字节或已核实业务事实证明重复时，才表述确定重复。
- 工程字段译成业务语言。商品编码未登记时，保留合同页/行、商品名称和实际合同编码，写“合同商品编码××未在商品资料中登记”；不显示内部知识库 ID、`CP-...` 主编码、`product_code`、`product_code_aliases` 或字段查找过程。实际印在业务文件中的编码保持原值，不能因其格式类似内部编码而删掉。
- 区分系统未完成复核与客户原件不清。有原图访问阻断证据时，写“系统无法读取现场原图，陈列列数和堆头面积尚未核验”；只知道复核未完成、没有访问阻断证据时，写“现场照片复核未完成，尚未确认陈列列数和堆头面积”。不能把任一情况改成照片模糊、材料缺失或陈列不合格。只有已实际复核原件并有可见依据时，才能说明图片不清、遮挡或范围不足等具体材料问题。
- 核销类型按 ZIP 名称中的唯一已登记标记选择。AI 对文档用途的观察不能改类，也不能把其他场景的缺件清单加入本场景。新提交的 ZIP 名称没有唯一类型标记时，直接打回且不调用 AI；原因只写该 ZIP 名称缺少标记或包含多个标记这一事实，不追加未经分析的缺件、重复或不可读结论。处理方式只说明如何将 ZIP 名称明确为一个已登记类型后重新提交；混合多包中的其他已知类型仍保留各自实际审核原因。

## 处理方式

- 只写与本条原因对应的具体操作或建议，明确处理哪个文件、对象、页、行或字段；建议只出现在此栏。
- 多个独立原因需要不同操作时逐项对应。不要重复错误事实、分析过程、置信度、审核结论或金额影响；不使用“请完善资料”“建议人工处理”等没有具体对象的套话。
- 不把处理方式写入错误原因、标题或回调摘要。所需建议继续保留在内部结果的操作字段并用于此栏，不能因精简原因而删除。
- 系统尚未完成复核时，处理方式写重新复核已提交的现场原图；已有访问阻断证据时写“恢复原图读取后重新核验”。不归咎客户材料，也不据此要求补拍或补交。确认原件确有清晰度、遮挡或范围缺口后，才按该缺口提出对应材料操作。商品资料登记问题用“登记合同使用的商品编码”等业务操作，不要求客户编辑工程字段。

## 涉及的业务文件

- 只列与当前问题相关的、实际提交的业务文件 basename；不显示目录或归档路径、文件角色、可见事实、证据叙述、原始或派生文件数量、参考资料、比较明细或读取限制。
- 文件关联仍按已验证的来源角色与控制确定，不能按名称猜测或用整包文件兜底。未提交的材料不能虚构成“已涉及业务文件”；知识库参考图、地图结果和临时派生图片不冒充客户提交文件。
- 按原始来源标识去重；不同来源的同名文件不能因 basename 相同合并或丢弃，显示时仍只用各自实际文件名。
- 完整路径、来源 ID、工作簿与派生图片的对应、角色和证据明细保留在内部技术 JSON。错误原因中需要定位时可保留业务文件名及必要页、行，不能将证据展开区移到文件名区域。

## 示例

以下是写法示例，不是所有场景通用的材料要求：

| 错误原因 | 处理方式 |
| --- | --- |
| `资料.zip` 的 ZIP 名称未标明核销类型。 | 在 ZIP 名称中注明一个已登记核销类型后重新提交。 |
| `维护费用-人员激励.zip` 的 ZIP 名称包含多个核销类型标记。 | 将 ZIP 名称改为仅含一个正确的核销类型后重新提交。 |
| 未提交 POS 电子表。 | 补交对应期间的 POS 电子表。 |
| `盖章POS.jpg` 的盖章区域模糊，无法辨认印章。 | 重新提供该图片，确保盖章区域清晰完整。 |
| `结算单.jpg` 与 `服务费结算单.jpg` 的主件、补充件关系不明。 | 明确主结算单，并标注另一份材料的用途及关联。 |
| `结算单.jpg` 申报 1,200 元，按合同计算应为 1,000 元，多报 200 元。 | 核对并更正该结算单的申报金额。 |
| `转账记录.jpg` 未显示完整交易日期。 | 提供显示完整交易日期的该笔转账记录。 |
| `合同.pdf` 第 2 页第 3 行“商品甲”的合同商品编码 A123 未在商品资料中登记。 | 核对该商品的合同编码；编码正确时登记到商品资料，填写有误时更正合同。 |
| 现场照片复核未完成，尚未确认陈列列数和堆头面积。 | 重新复核已提交的现场原图，确认陈列列数和堆头面积。 |
| 系统无法读取现场原图，陈列列数和堆头面积尚未核验。 | 恢复原图读取后重新核验。 |

“知识库主编码 CP...，且 product_code_aliases 未登记合同编码”应转为上述商品编码原因；“本次无法完成要求的原始分辨率独立复核，未形成实体列数或占地面积的有效复核结论”应转为上述复核未完成原因。工程细节仍保留内部证据，不加入客户原因或处理方式。

维护费用回调只列对应原因，例如：

```markdown
- 未提交 POS 电子表。
- 盖章POS.jpg 的盖章区域模糊，无法辨认印章。
- 结算单.jpg 与服务费结算单.jpg 的主件、补充件关系不明。
```

## 内部证据与判断

本规范仅规定客户文案，不改变材料安全检查、证据提取、核销规则、金额计算、状态或 Schema。完整来源、观察、控制结果、通过事实、置信度、影响、结论和操作字段继续保留，供内部审计、技术档案和既有独立检查投影使用；不能把这些字段拼成客户错误原因或重复塞进处理方式。没有错误时不生成错误条目，也不拿通过事实充当原因。

生成前确认每条原因都有具体事实依据、每项建议只在处理方式，两栏没有互相重复，业务文件区域只有相关实际文件名。回调与落盘摘要使用同一原因内容，不附处理方式或重新组织分析过程。

旧材料诊断的客户投影必须遵循唯一 ZIP 名分类：名称唯一明确且与已保存场景一致时，不再将旧 `scenario_unconfirmed` 当作客户错误；仅在内存副本排除该条，原始结果和证据保留。缺件、不可读、实际金额差异及角色关系问题继续显示。分类错误按明确诊断代码归为费用类型，不因正文含金额词而归到金额复算。
