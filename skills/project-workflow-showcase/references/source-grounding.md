# 源码依据

使用本指南决定哪些内容可以作为事实出现在展示页中。扫描器只定位可能的证据；文件名和目录名绝不能证明行为。

## 按证据顺序阅读

1. 阅读项目根目录和输出位置所适用的每个 `AGENTS.md`。
2. 阅读主 README、软件包/构建清单，以及存在时的项目级 Skill 或操作入口。
3. 阅读真实运行入口及其直接调用的模块。
4. 阅读约束这些入口的契约、schema、政策、配置默认值和数据模型。
5. 阅读展示重要正常路径、拒绝路径、恢复、安全边界和输出契约的测试。
6. 只有核对架构或运维文档与代码、测试仍一致后，才使用这些聚焦文档。
7. 检查范围内文件的当前 Git 差异。脏工作树可能比 `HEAD` 新；不得默默只描述最后一次提交。

制作技术展示页时，不得读取真实 `input/`、`result/`、`output/`、`.runtime/`、worktree、日志或凭据内容，
除非用户明确要求使用这些数据且披露安全。只有明确标为夹具时，才能描述仓库示例和夹具。

## 维护结论台账

阅读时维护一个紧凑的内部台账：

| 结论 | 证据路径 | 类型 | 置信度 | 用途 |
|---|---|---|---|---|
| 系统如何启动 | 入口 + 测试 | 已实现 | 高 | 工作流 |
| 某项政策的意图 | 只有政策文档 | 已记录 | 中 | 边界说明 |
| 未来可能存在的内容 | 当前无实现 | 拟议 | 低 | 默认省略 |

规则：

- 每项结论必须有源码内容依据，不能根据路径名称猜测。
- 行为结论优先使用代码加测试；契约结论优先使用 schema 加校验器；只有文档意图才能仅依赖文档。
- 冲突时以可执行代码和通过的测试为准；若冲突对读者重要，应明确披露。
- 数量必须从明确的来源集合计算，并在标签中说明计数规则；否则省略该数字。
- 绝不能把推断提升为标题事实。必要推断放在明确标记的说明中，并引用促成推断的文件。

## 选择项目专属章节

只有能帮助解释某种关系且有证据时才加入章节。常见候选包括：

- 目标及运行边界；
- 架构或职责分层；
- 端到端运行工作流；
- 组件与角色图；
- 状态、数据、schema 或产物生命周期；
- 外部接口及安全边界；
- 失败、重试、恢复或人工接管；
- 仓库地图及重要文件职责；
- 验证和验收契约。

不要强迫每个项目包含所有候选。小型库可能更需要 API 表面和调用图，而不是部署或运维章节；
静态站点可能需要构建/内容流，而不是 Agent、队列或 schema。

## 发布可见来源

- 在 `data-sources` 中使用项目相对的正斜杠路径。
- 在相关说明旁以来源标签再次可见地显示相同路径。
- 引用最小但有效的集合：入口、控制契约及证明测试，通常比罗列二十个路径更有信息量。
- 不得发布绝对路径、凭据、环境值、用户记录、临时文件、生成证据或复制的源码正文。
- 只有帮助读者定位行为时才使用简短代码标识符。避免长代码清单；展示页解释关系，不重新发布仓库。
