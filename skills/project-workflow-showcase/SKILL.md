# 项目工作流技术展示

把真实存在的仓库组织为一个清晰的技术故事。先阅读项目，确保每项结论都可追溯到当前文件，
并交付原创的独立 HTML，不能只是给参考页面改名。

本仓库已有展示页存放在 [assets/project-workflow-demo.html](assets/project-workflow-demo.html)，
维护本项目展示时沿用该位置。它保留既有项目说明，不作为新项目的内容来源或生成模板。

## 必须保持的边界

- 以项目源码、适用的 `AGENTS.md`、清单、契约、测试及当前工作树变更为权威来源。
- 示例 HTML 只能作为成品质量基准。不得把它当作内容来源，不得复制其 DOM/CSS，也不得把它作为生成模板。
- 不得虚构模块、Agent、阶段、API、数量、生产结果或已完成能力。无法可靠推导的数字应省略。
- 区分已实现行为、文档意图、推断和拟议未来工作。主架构中不得出现不确定结论。
- 不得读取或暴露秘密、凭据、私钥、`.env` 值、真实业务输入、运行证据、日志或生成结果目录。
- 保留用户的无关变更。只生成用户要求的 HTML 及明确要求的文档；不得顺带重构项目。
- 交付物必须自包含：CSS、JavaScript、图标、图示和数据均内联。不得使用 CDN、远程字体、远程图片、`fetch` 或 iframe。

## 执行从源码到展示页的工作流

1. **明确范围。** 确定项目根目录、目标输出路径、预期读者、当前源码状态及可选视觉参考。
   默认在项目 `docs/` 目录下输出一个可独立打开的 `.html`。

2. **在不读取敏感数据的前提下盘点。** 从本 Skill 目录运行 bundled scanner：

   ```bash
   python scripts/inspect_project.py --root /path/to/project --pretty
   ```

   Windows 环境中，如果仓库通常使用该启动器，则改用 `py -3`。盘点结果只用于定位证据，不能证明架构。

3. **阅读证据。** 遵循 [source-grounding.md](references/source-grounding.md)。先完整阅读每个适用指令文件，
   再阅读能够证明运行时、边界、数据流、接口、失败行为和验证的最小高信号文件集。检查测试所保证的真实行为。

4. **在工作记忆中建立结论台账。** 对每个拟议章节记录结论、项目相对路径、置信度，以及行为是已实现还是只写在文档中。
   写 HTML 前删除无依据结论。

5. **选择技术主线。** 从最能解释项目存在原因的端到端路径开始。只有当前证据支持时，才增加架构、组件、文件、契约、
   外部边界、失败和验证内容。章节数量与术语必须适应该项目。

6. **设计原创页面。** 遵循 [experience-contract.md](references/experience-contract.md)。
   参考页面只用于对齐清晰度、信息密度、完成度和导航性，不得模仿其颜色、措辞、布局尺寸、样例数据或标记结构。

7. **让来源可见。** 每个事实性 `<section>` 都必须有一个以竖线分隔、包含项目相对路径的 `data-sources` 属性，例如：

   ```html
   <section id="workflow" data-sources="README.md|src/runner.py|tests/test_runner.py">
   ```

   同时在该章节内以紧凑来源标签可见地渲染这些路径。保持相对路径，不得暴露机器专属绝对路径。

8. **只实现真实交互。** 锚点导航、页签、筛选或折叠面板必须支持键盘和指针操作。
   删除暗示不存在行为的装饰控件。不得创建虚假运营仪表盘。

9. **运行确定性验证。** 调用：

   ```bash
   python scripts/validate_showcase.py /path/to/output.html --project-root /path/to/project --pretty
   ```

   修复每个错误。警告必须进入审查，不能自动视为失败。

10. **在真实浏览器中验证。** 以桌面和窄屏/移动端宽度打开文件。操作每个控件、截图、检查控制台、
    测试本地导航和键盘焦点，并确认页面没有横向溢出。只有完成基于源码的页面后，才与视觉参考比较。
    持续迭代，直到关闭参考页面后，新页面本身仍然连贯。

11. **准确交接。** 报告绝对输出路径、项目快照或脏工作树依据、生成章节、确定性及浏览器检查，
    以及仍存在的源码级不确定性。不得把无依据内容称为“完整”。

## 验收契约

只有满足以下条件才接受结果：

- 阅读者无须打开源码，就能说明项目目标、主要组件、端到端流程、控制/数据边界、失败路径和验证方式；
- 每个事实性章节都指向现有的项目相对证据；
- HTML 不含真实秘密、业务记录、远程依赖、虚假指标、无依据能力、占位文字或无效控件；
- 页面可离线运行、浏览器控制台无错误、桌面和移动端均可用，视觉上有明确设计，而非通用卡片网格；
- bundled validator 通过，并且经过浏览器测试的是最终文件，而不是临时副本。
